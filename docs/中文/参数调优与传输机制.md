# SSCP 参数调优与传输机制说明

[Transport Tuning & Mechanisms (English)](../English/TransportTuning.md) · [使用手册](使用手册.md) · [项目 README](../../README.md)

本文说明 SSCP 传输层当前提供的编译期可调参数、不同网络环境下的推荐配置，以及可选动态按包位图 SACK、延迟 ACK 与拥塞控制机制的设计边界。

---

## 1. 编译期可调参数总表（`sscp.h`）

以下宏均带 `#ifndef` 保护，可通过 `-D<NAME>=<VALUE>` 在不同环境或测试场景中按需覆盖，无需修改源码：

| 参数宏 | 默认值 | 含义与作用 |
|---|---|---|
| `SSCP_ACK_BATCH_MAX` | `2U` | 延迟批量 ACK 阈值（RFC 5681：默认每 2 个满包回一次 ACK）。 |
| `SSCP_ACK_DELAY_MS` | `4U * SSCP_TICK_SCALE` | 延迟 ACK 定时器上限（默认 `4 ms`）；实际延迟取 `min(srtt >> 2, SSCP_ACK_DELAY_MS)`，下限 `1 ms`。 |
| `MTU` | `1460` | SSCP 单个传输包最大字节数，`MSS = MTU - sizeof(struct sscp_hdr)`（`30 B` 首部，默认 `MSS = 1430`）。 |
| `SSCP_IW_SEGS` | `10U` | 初始拥塞窗口段数（RFC 6928 IW10，即初始 `cwnd = 10 * MSS`）。 |
| `SSCP_RTO_INIT` | `500U * SSCP_TICK_SCALE` | 初始重传超时（`500 ms`）；获得 RTT 样本后动态钳位在 `[SSCP_RTO_MIN, SSCP_RTO_MAX]`（`200 ms ~ 2000 ms`）。 |
| `CWND_WIN_MAX` | `1 << 20`（1 MiB） | 拥塞窗口上限。长肥管道（高带宽 × 高 RTT）按需增大。 |
| `SEND_WIN_INIT` / `RECV_WIN_INIT` / `SSCP_RECV_LIMIT` | `1 << 24`（16 MiB） | 发送/接收滑动窗口初始值与接收缓冲区上限。 |
| `SSCP_TICK_SCALE` | `1U` | 每毫秒 tick 数（真实 UDP 默认 `1U` = 1 ms；虚拟仿真默认 `1000U` = 1 μs）。 |

## 2. 不同网络环境的推荐参数

> **原则**：`main` 默认值面向通用网络（覆盖短 RTT WiFi、有限队列 WAN 与长距离跨洋链路），优先保证 ACK 时钟稳定、HyStart 延迟检测灵敏且不污染 SRTT。在特定部署环境测试时，只需通过编译参数切换即可。

### 2.1 通用默认 / 局域网 / WiFi（RTT 5–50 ms）

直接使用默认配置即可：

```sh
cmake -S test -B build -DCMAKE_BUILD_TYPE=Release
```

- `SSCP_ACK_BATCH_MAX=2U`、`SSCP_ACK_DELAY_MS=4 ms` 与动态 `srtt / 4` 上限保证在 10 ms 级短 RTT 下不打断 ACK 时钟，也不稀释 CUBIC HyStart 的延迟采样。

### 2.2 跨洋高 RTT / 隧道加密封装 / 弱上行链路（RTT 150–250 ms）

当底层叠加了 UDP 隧道、AEAD 加密或协议混淆（存在外层包头/填充开销），且希望进一步压缩返程 ACK 包率或跑满高 BDP 管道时，可按需覆盖参数：

```sh
cmake -S test -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_FLAGS="-DMTU=1200 -DSSCP_ACK_BATCH_MAX=4U -DSSCP_ACK_DELAY_MS='(8U*(SSCP_TICK_SCALE))' -DCWND_WIN_MAX='(4U<<20)'"
```

- **调低 `MTU`**（如 `1200`–`1360`）：为外层 UDP/IPv6/PPPoE/加密填充预留空间，避免中间路径分片丢包。
- **适度放大 `SSCP_ACK_BATCH_MAX`**（如 `4`）：减少长距离返程小包数量；不建议在通用默认中设得过大（例如 `8:1 / 15 ms`），否则会在短 RTT 场景与丢包小窗口期显著拉长恢复时间并抬高 SRTT。
- **放大 `CWND_WIN_MAX`**：例如 `100 Mbps × 200 ms` 管道 BDP 为 `2.5 MB`，默认 `1 MiB` 窗口上限会将单流吞吐限制在 ~`40 Mbps`，增大到 `4 MiB` 可释放完整管道带宽。

### 2.3 无延迟 ACK 对照测试（1:1 逐包确认）

用于基准回归对比或极低时延内网测试：

```sh
cmake -S test -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_FLAGS="-DSSCP_ACK_BATCH_MAX=1U"
```

### 2.4 嵌入式 / 小内存环境

按可用 SRAM 收紧窗口与包长即可（需确保 `MTU >= 320` 以容纳完整可选 SACK 位图）：

```sh
-DMTU=576 -DCWND_WIN_MAX=32768 -DSSCP_RECV_LIMIT=32768 -DSEND_WIN_INIT=32768 -DRECV_WIN_INIT=32768
```

## 3. 延迟 ACK 触发规则

为兼顾省 ACK 与快速丢包恢复，`sscp_schedule_ack()` 在以下任一条件满足时**立即发送 ACK**，不等待延迟定时器：

1. 收到乱序包或重复包（`sscp_process_data` 直接回复）；
2. 刚刚填补了乱序空洞（`filled_hole`），或接收队列 `rcv_buf_q` 中仍有未填平空洞；
3. 收到短包（`payload_len < MSS`，常见于消息尾部或交互式小包）；
4. 本端正处于快速恢复状态（`fr_active`）；
5. 已累积未确认包数达到 `SSCP_ACK_BATCH_MAX`。

其余情况才启动延迟定时器，超时时间为 `clamp(srtt >> 2, 1 ms, SSCP_ACK_DELAY_MS)`（`srtt == 0` 时取 `SSCP_ACK_DELAY_MS`）。

## 4. 可选动态按包位图 SACK 机制

SSCP 采用“**按离散包发送、按字节流维护**”的模型：`sscp_send()` 切片入队的每个 `sscp_buf` 不会在后续重分片或合并，并获得严格递增的 32 位 `pkt_id`（重传时保持不变）。

### 4.1 线格式与零膨胀设计

- **固定首部 `struct sscp_hdr` 保持精确 `30 B`**（字段：`seq`, `ack`, `pkt_id`, `fd`, `wnd`, `len`, `cksum`, `flags`, `time_val`）。
- **DATA 包与无乱序普通 ACK**：不设置 `SSCP_FLAG_SACK`，**0 B SACK 额外开销**。
- **乱序 ACK（`SSCP_FLAG_SACK = 0x100`）**：仅当 `rcv_buf_q` 非空时，纯 ACK 在首部后追加动态扩展块，并把扩展字节数写入 `sh->len`（由 `sscp_input()` 统一校验长度与整包校验和）：

```text
+--------------------+---------------+-----------------+------------------------+
| sscp_hdr (30 B)    | base_id (4 B) | map_words (2 B) | map[0..map_words-1]    |
| flags |= FLAG_SACK | = rcv_pkt_nxt |   (1 .. 64)     | (4 B .. 256 B, big-end)|
+--------------------+---------------+-----------------+------------------------+
```

- 位图中 bit `i` 对应数据包 `base_id + i`（bit `0` 为首个缺失包，恒为 `0`；已收乱序包置 `1`）。
- 长度按最高非零 word 动态裁剪：仅有 1~32 个乱序包时仅多占 **`10 B`**；最多 `64` word（`2048` 包 ≈ `2.8 MiB` 跨度）。

### 4.2 发送侧处理与恢复策略

1. **单趟扫描 `snd_q`**（`sscp_sack_mark_and_retransmit`）：
   - 位图置 `1`：标记 `sb->sacked = 1` 并累加 `ss->sacked_bytes`。
   - 位图置 `0` 且未标记 `sacked` / `retransmitted`：头洞（`pkt_id == base_id`）立即快重传；非头洞满足 RFC 6675 乱序门限 `highest_id >= pkt_id + 3` 后触发快重传；单次 ACK 最多补 `RETRANS_GAP_MAX`（`4`）个洞，防止浅队列突发抖动。
2. **单次快重传与 RTO 联动**：
   - 每个丢包仅快重传一次（`sb->retransmitted` 保护），若重传包再次丢失交由 RTO 兜底；无实际补发时不重置 `t_retrans`。
   - 首轮 RTO（`timeout_count == 0`）保留 `sb->sacked` 状态，仅清除未 SACK 包的 `retransmitted` 标志；连续第二次 RTO 清空所有 `sacked` 与 `sacked_bytes`（防范对端 reneging）。
3. **在途量与窗口约束（`sscp_output`）**：
   - 接收流控窗口 `snd_wnd` 约束总在途字节 `raw_flight = schedule_next->seq - snd_una`；
   - 拥塞窗口 `cwnd` 约束实际网络在途量 `pipe = raw_flight - sacked_bytes`，恢复期可继续平滑推进新数据。
4. **RTT 回显与校验和**：
   - 携带 `SSCP_FLAG_SACK` 的纯 ACK 照常回显 DATA 时间戳更新 `srtt` / `rtt_base`。
   - 校验和采用严格别名安全的 `sscp_checksum()`（`memcpy` 16-bit 累加），避免 `-O3` 编译优化下对打包首部的指令重排风险。

## 5. 拥塞控制算法一览

| 算法枚举 | 适用特征 | 核心行为 |
|---|---|---|
| `SSCP_CC_PROB`（默认） | 丢包与排队并存的公网/跨洋链路 | 基于 `srtt - rtt_base` 与 `p_ema` 构造连续拥塞概率 `q`；支持概率加权指数慢启动、恢复期持续自适应，可通过 `sscp_prob_configure(ss, rtt_span_ms, loss_q16)` 标定。 |
| `SSCP_CC_AIMD` | 基准对照 / 保守公平竞争 | 标准 Reno 风格加性增、乘性减。 |
| `SSCP_CC_CUBIC` | 高 BDP 长距/高带宽链路 | RFC 9438 CUBIC 曲线增长，内置 HyStart 延迟慢启动退出机制。 |
